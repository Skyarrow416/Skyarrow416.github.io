HackTheBox-Rebound

漁王還想 繼續做漁王 而海港已經 不知去向

此刻他醉倒在洗浴中心 沒有潮汐的夢 胸口已暮色蒼茫

靶机ip：10.129.232.31

攻击链路概要

端口扫描

使用RustScan快速扫描所有开放端口，然后调用nmap进行服务版本探测
目标：识别目标系统类型和开放的服务

nxc对smb协议进行常规枚举

使用NetExec（nxc）对SMB服务进行匿名枚举

-u ‘guest’ -p ‘’: 使用guest用户空密码进行匿名访问

–shares: 枚举可访问的共享文件夹

将域名写入hosts，顺便探查可读共享文件夹Shared。

添加DNS解析记录，方便后续Kerberos认证（Kerberos要求使用FQDN）

没东西，继续枚举用户

尝试使用–users参数枚举域用户，但未返回结果

rid爆破，爆破范围设为10000

RID（Relative Identifier）爆破：通过枚举RID来发现域用户和组

RID是Windows对象的相对标识符，用户从1000开始递增

这里设置范围为10000，足以覆盖大部分用户账户

将用户写入文件，尝试使用AS-REP ROASTING攻击。

AS-REP Roasting攻击原理：

  • 针对设置了”不需要Kerberos预认证”属性的用户
  • 可以在不知道密码的情况下请求到AS-REP响应
  • AS-REP响应中包含用户密码加密的部分，可以离线破解

得到hash后使用john破解，但这里并没有破解出来。

使用John the Ripper尝试破解AS-REP哈希

使用rockyou.txt字典进行破解，但密码不在常见字典中

不过我们已经知道了jjones是无需预认证的用户，我们可以利用该用户进行无密码的Kerberoasting

Kerberoasting攻击原理：

  • 请求服务账户的TGS（服务票据）
  • TGS使用服务账户的密码加密，可以离线破解
  • 关键技巧：使用-no-preauth参数，利用jjones的无预认证特性
  • 不需要jjones的密码就能以其身份请求其他服务的TGS票据

得到两个哈希，继续使用john破解

最终破解出了ldap_monitor的密码

John成功破解ldap_monitor的TGS哈希

密码：1GR8t@$$4u（看起来是”1 Great ass for you”的变体）

进行密码喷洒，查询使用相同密码的用户

密码喷洒（Password Spraying）：

  • 使用破解出的密码1GR8t@$$4u在所有用户账户上尝试
  • –continue参数：即使某个账户认证失败也继续尝试其他账户
  • 目的：发现多个用户使用相同密码的情况（弱密码管理）

得到oorend和ServiceMgmt，其中ServiceMgmt是guest，故用oorend进行一波bloodhound收集。

但在使用rusthound进行收集时报错了

尝试使用RustHound收集BloodHound数据

错误：LDAP签名要求（strongerAuthRequired）

DC要求启用完整性检查，需要使用LDAPS或Kerberos认证

那么先请求票据，然后再使用票据进行检查

解决LDAP签名问题的方案：

  • 使用impacket-getTGT获取oorend的Kerberos TGT票据
  • 将票据保存到环境变量KRB5CCNAME
  • bloodhound-python使用-k参数进行Kerberos认证
  • 这样可以绕过LDAP签名要求

BloodHound分析 - 第一个关键权限：

  • OOREND@REBOUND.HTB对SERVICEMGMT@REBOUND.HTB拥有AddSelf权限
  • AddSelf权限：允许将自己添加到目标组中

BloodHound分析 - 第二个关键权限：

  • SERVICEMGMT@REBOUND.HTB组对SERVICE USERS@REBOUND.HTB拥有GenericAll权限
  • GenericAll：完全控制权限，可以修改组成员、属性等

查看SERVICE USERS@REBOUND.HTB，发现WINRM_SVC@REBOUND.HTB在此组中，该成员可以远程登录主机。

攻击路径分析：

  1. oorend有AddSelf权限 → 可以将自己加入ServiceMgmt组
  2. ServiceMgmt组有GenericAll权限 → 可以完全控制SERVICE USERS OU
  3. winrm_svc在SERVICE USERS OU中 → 可以对其进行攻击
  4. winrm_svc可以远程登录 → 获取Shell的目标账户

那么利用链已经清晰，开始利用

首先将OOREND@REBOUND.HTB加入SERVICEMGMT@REBOUND.HTB

使用bloodyAD工具执行权限提升链：

  • add groupMember: 将oorend添加到ServiceMgmt组
  • 这样oorend就继承了ServiceMgmt组的所有权限

给 oorend 赋予对整个 OU 的全部权限

现在oorend是ServiceMgmt组成员，利用GenericAll权限：

  • add genericAll: 直接给oorend用户赋予对SERVICE USERS OU的GenericAll权限
  • 这样即使不通过组也能直接操作OU中的对象
  • OU=SERVICE USERS,DC=REBOUND,DC=HTB: LDAP的DN格式

使用影子凭据攻击

影子凭据（Shadow Credentials）攻击原理：

  • 利用GenericAll权限修改目标用户的msDS-KeyCredentialLink属性
  • 添加自己生成的公钥证书到该属性
  • 使用对应的私钥请求该用户的TGT
  • 通过PKINIT协议获取用户的NT哈希
  • certipy-ad的auto模式会自动完成整个流程

得到哈希，登录拿到userflag

使用Evil-WinRM通过Pass-the-Hash登录：

  • -H: 使用NT哈希认证（无需明文密码）
  • winrm_svc有WinRM远程管理权限

查看当前进程

进程枚举目的：

  • 查找是否有其他用户登录（Session ID不为0）
  • 发现explorer.exe运行在Session ID 1 → 有用户在控制台登录
  • 可能可以窃取该用户的凭据

发现explorer的Session ID是1，表明有人登录，上传RunasCs.exe进一步枚举登录用户

qwinsta是显示有关会话主机的信息的命令

RunasCs工具：

  • 可以以其他用户身份运行命令（类似runas）
  • -l 9: 以SYSTEM级别运行（最高权限）
  • qwinsta: Windows命令，查询会话信息
  • 目的：确认具体是哪个用户登录

那我们可以使用RemotePotato0来窃取tbrady的ntlm哈希。

RemotePotato0攻击原理：

  • 利用DCOM激活和NTLM中继
  • -m 2: 模式2，针对特定会话
  • -s 1: 目标Session ID 1（tbrady的会话）
  • 需要在本地设置socat中继RPC流量
  • 触发目标会话的COM对象创建，截获NTLM认证

先传好工具，本地设置好socat中继

socat配置：

  • 监听本地135端口（RPC Endpoint Mapper）
  • 将流量转发到目标的9999端口
  • fork,reuseaddr: 允许多个连接和端口重用

破解hash，得到密码

使用John the Ripper破解NTLMv2哈希

密码：543BOMBOMBUNmanda

BloodHound分析tbrady的权限：

  • tbrady对delegator$（机器账户）拥有ReadGMSAPassword权限
  • GMSA（Group Managed Service Account）：组托管服务账户
  • ReadGMSAPassword权限允许读取GMSA账户的密码

tbrady对该机器用户有ReadGMSAPassword，这里使用nxc

GMSA密码读取：

  • –gmsa参数：枚举并读取GMSA账户密码
  • GMSA密码由域控自动管理，定期轮换
  • 有ReadGMSAPassword权限的用户可以读取当前密码

得到哈希。

BloodHound分析delegator$的权限：

  • delegator$对DC01$（域控机器账户）拥有AllowedToDelegate权限
  • 这是约束委派（Constrained Delegation）配置
  • 允许delegator$模拟用户访问DC01上的特定服务

进一步发现该机器账户对DC01有AllowedToDelegate权限

使用impacket-findDelegation查找委派配置

但是这里不能使用经典的getST，因为administrator没有被配置为允许 Kerberos 约束委派

约束委派限制：

  • Administrator账户标记为”Account is sensitive and cannot be delegated”
  • 这是一个安全设置，防止高权限账户被委派
  • 无法直接使用delegator$的约束委派模拟Administrator
  • 需要寻找其他攻击路径

不过这里可以使用KDC+RBCD的组合

攻击策略：资源型约束委派（RBCD）+ KDC欺骗

  • 思路：既然不能直接委派到Administrator，就换个角度
  • 利用RBCD让其他账户可以被模拟
  • 然后通过该账户的权限链接到DC01
  • 最终实现DCSync攻击

我们的目标选择之前控制的服务账户ldap_monitor

第一步用bloodyAD为该账户加上rbcd属性

RBCD配置：

  • 为ldap_monitor添加msDS-AllowedToActOnBehalfOfOtherIdentity属性
  • 允许delegator$代表其他用户模拟到ldap_monitor
  • 这是资源型约束委派（Resource-Based Constrained Delegation）

验证RBCD配置：

  • ldap_monitor现在显示为”Resource-Based Constrained”委派类型
  • DelegationRightsTo: delegator$ - 可以委派到delegator$
  • 现在形成了委派链：ldap_monitor → delegator$ → http/dc01.rebound.htb

接着用该票据请求机器账户DC01的票据

第三步：利用delegator$的约束委派

  • 现在以dc01$身份持有访问delegator$的票据
  • delegator$对http/dc01.rebound.htb有约束委派权限
  • 使用-additional-ticket参数提供dc01$的票据作为证据
  • 再次执行S4U2Proxy，将票据转换为dc01$访问http/dc01的票据

接着使用该票据dump哈希

第四步：DCSync攻击

  • 使用dc01$的票据执行secretsdump
  • dc01$作为域控机器账户具有复制目录更改的权限
  • 可以通过DRS（Directory Replication Service）协议dump域数据库

管理员登录，拿到rootflag

最后一步：Pass-the-Hash登录

  • 使用Administrator的NT哈希登录
  • 获得域管理员权限
