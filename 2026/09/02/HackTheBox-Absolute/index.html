HackTheBox-Absolute

大梦一场的董二千先生 推开窗户 举起望远镜 眼底映出 一阵浓烟 前已无通路 后不见归途

知识点与路径总结

靶机信息：10.129.232.60，域 absolute.htb，Windows Server 2019 域控（DC），难度 Hard。

核心知识点

  • OSINT 用户名收集：从网站图片 EXIF 元数据（Author/Artist 字段）提取真实姓名，按常见企业命名规则批量生成用户名字典。
  • Kerberos 用户枚举：用 kerbrute userenum 通过 KDC 的预认证响应差异（KDC_ERR_PREAUTH_REQUIRED vs PRINCIPAL_UNKNOWN）验证域内有效用户名，无需任何凭据。
  • AS-REP Roasting：针对关闭了 Kerberos 预认证（DONT_REQUIRE_PREAUTH）的账户，离线爆破 AS-REP 报文中用用户口令派生密钥加密的部分。
  • 禁用 NTLM 环境下的 Kerberos 认证：STATUS_ACCOUNT_RESTRICTION 表明目标禁用了 NTLM，必须先 getTGT 申请 Kerberos 票据（ccache）再走 -k 认证。
  • 信息泄露横向移动：用户描述字段泄露 svc_smb 口令 → SMB 共享中的 test.exe 运行后通过 LDAP 流量抓包泄露 m.lovegod 口令。
  • 基于 ACL 的权限提升：WriteOwner → dacledit 授予 FullControl → 加组 → GenericWrite，借助 BloodHound 分析并利用 ACL 攻击链。
  • 影子凭据（Shadow Credentials）攻击：利用 msDS-KeyCredentialLink 属性写入，用 certipy shadow auto 为目标账户申请证书并 PKINIT 获取 TGT 与 NT hash。
  • KrbRelay / KrbRelayUp 本地提权：Kerberos 中继实现本地系统提权（受”受保护的用户”组限制的注意事项）。

攻击路径

  1. 端口扫描 → 识别为域控（53/88/389/636/…）。
  2. 网站图片 EXIF → 提取 6 个作者姓名 → 生成用户名字典。
  3. kerbrute 验证出 6 个有效用户 → impacket-GetNPUsers 发现 d.klay 可 AS-REP Roasting。
  4. john 爆破得到 d.klay / Darkmoonsky248girl。
  5. NTLM 被禁用（STATUS_ACCOUNT_RESTRICTION）→ getTGT 走 Kerberos → 枚举用户，描述字段泄露 svc_smb / AbsoluteSMBService123!。
  6. svc_smb 读取 Shared 共享 → 运行 test.exe 抓包 → LDAP 流量泄露 m.lovegod / AbsoluteLDAP2022!。
  7. BloodHound 分析 ACL 链：m.lovegod（Networkers 组）→ WriteOwner → Network Audit → GenericWrite → winrm_user。
  8. owneredit + dacledit + 加组 → 对 winrm_user 做影子凭据攻击（certipy shadow auto）→ 拿到 TGT/NT hash → evil-winrm 登录取得 user.txt。
  9. 上传 KrbRelayUp 等工具，利用 KrbRelay 技术本地提权至 SYSTEM（root）。

原理：JPEG 等图片在保存时会写入 EXIF/XMP 元数据，其中 Artist、Author、Creator 等字段常常保留了图片制作者的真实姓名。在域渗透的初始信息收集阶段，这些真实姓名是构造用户名字典的绝佳来源——因为企业的 AD 账户命名往往直接从员工姓名派生（如 j.roberts、jroberts）。

针对每张图片的作者生成用户名字典

使用kerbrute进行验证

原理：Kerberos 预认证阶段，KDC 对”用户不存在”和”用户存在但需要预认证”会返回不同的错误码（KDC_ERR_C_PRINCIPAL_UNKNOWN 与 KDC_ERR_PREAUTH_REQUIRED）。kerbrute 正是利用这一差异，在无需任何有效凭据、且通常不会触发账户锁定的情况下，快速判定哪些用户名在域中真实存在，从而把庞大的猜测字典收敛为少数几个确认账户。

做AS-Rep-Roasting尝试

原理：正常情况下 Kerberos 要求客户端在 AS-REQ 中携带用时间戳加密的预认证数据，以证明自己掌握口令。若某账户设置了 DONT_REQ_PREAUTH 标志（即关闭预认证），任何人都可以直接向 KDC 索要该用户的 AS-REP，而其中一段是用用户口令派生的密钥加密的。攻击者把这段密文离线拿去爆破，命中即得到明文口令——这就是 AS-REP Roasting。下面的输出中只有 d.klay 未设置预认证，因此仅它返回了可爆破的 $krb5asrep$ 哈希。

使用john破解d.klay的哈希

得到凭据d.klay/Darkmoonsky248girl

但是密码验证行不通，我们需要请求票据。

STATUS_ACCOUNT_RESTRICTION 通常意味着禁用了NTLM，并且需要使用Kerberos进行身份验证。

原理：NTLM 是”口令直接参与挑战-响应”的认证协议，管理员可通过组策略在域内禁用它。一旦禁用，凭 用户名+口令 走 NTLM 的路径全部报 STATUS_ACCOUNT_RESTRICTION。此时必须改用 Kerberos：先用 getTGT 拿到 TGT 并保存为 ccache，导出 KRB5CCNAME 后，所有工具加 -k 参数即可用票据认证。这也是本靶机后续几乎每一步都要”先 getTGT 再操作”的原因。

同样请求票据并进一步枚举，使用bloodhound-python

分析得到，M.LOVEGOD@ABSOLUTE.HTB是NETWORKERS@ABSOLUTE.HTB的成员，而该组对NETWORK AUDIT@ABSOLUTE.HTB拥有WriteOwner权限，且NETWORK AUDIT@ABSOLUTE.HTB对WINRM_USER@ABSOLUTE.HTB有GenericWrite权限。

原理：AD 中每个对象都有一个 DACL（自主访问控制列表）描述”谁能对它做什么”。BloodHound 通过 LDAP 收集这些 ACL 关系并绘成图，帮助发现隐蔽的提权链。这里涉及两种关键权限：WriteOwner 允许把对象的属主改成自己，成为属主后即可给自己授予任意权限（如 FullControl）进而修改成员关系；GenericWrite 允许写目标对象的大部分属性——对用户对象而言，这足以写入 msDS-KeyCredentialLink（影子凭据）来完全接管该账户。

那么攻击链就是M.LOVEGOD到NETWORK AUDIT@ABSOLUTE.HTB再到WINRM_USER@ABSOLUTE.HTB

现在可以对WINRM_USER进行影子凭据攻击，上次用的是pywhisker，这次用certipy。

原理：影子凭据（Shadow Credentials）攻击利用了用户/计算机对象的 msDS-KeyCredentialLink 属性——它本用于 Windows Hello for Business，存放账户的公钥凭据。当我们对目标拥有 GenericWrite 等写权限时，可以往该属性写入自己生成的一对证书公钥；随后用对应私钥通过 PKINIT 向 KDC 请求 TGT，即可”以目标身份”认证，并进一步 U2U 解出其 NT hash。相比改密码，它不会锁死原用户、且用完可还原，隐蔽性更好。certipy shadow auto 把”生成证书→写入→PKINIT→取回 NT hash→还原属性”整条流程自动化了。

注意要重新申请票据。

现在导入票据拿到userflag

提权方面，这里用的是一种当时非常新的技术KrbRelay

原理：KrbRelay/KrbRelayUp 的核心是把 Kerberos 认证做中继。它诱导本机的 SYSTEM 上下文向攻击者控制的入口发起 Kerberos 认证，再把这张服务票据中继到 LDAP/SCM 等本地服务，进而配置基于资源的受限委派（RBCD）或直接创建高权限服务，最终在本机取得 SYSTEM。它填补了当年”本地无 NTLM 中继可用”场景下的提权空白。

使用工具KrbRelayUp

但是由于我们所处的用户都在受保护的用户中（NTLM认证的原因），所以我们不能直接使用它来获得一个shell。

原理：”受保护的用户”（Protected Users）组会对成员强制施加更严格的安全策略：禁用 NTLM 认证、禁止 DES/RC4 等弱加密、禁止无约束/受约束委派、且 TGT 生命周期被缩短。这正是本靶机一路强制走 Kerberos 的根源，也意味着 KrbRelayUp 默认流程里依赖 NTLM/RC4 的环节无法直接套用，需要针对性调整。
